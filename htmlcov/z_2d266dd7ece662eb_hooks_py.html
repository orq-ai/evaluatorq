2

89class SimulationHooks(Protocol): 

90 """Protocol for simulation lifecycle hooks. 

91 

92 Implementations are injected via ``simulate(hooks=...)`` or 

93 ``SimulationRunner(hooks=...)``. Methods may be sync or async (declared with 

94 ``MaybeAsync`` returns and driven via ``await_maybe``); ``async def`` is 

95 preferred — a sync implementation works but emits a ``DeprecationWarning``. 

96 Either way they run on the async event loop, so keep them fast — offload 

97 blocking work with ``asyncio.to_thread``. 

98 

99 Exception policy: only ``on_turn_complete`` is exception-guarded by the 

100 runner — it fires inside ``run()``'s catch-all, which would otherwise 

101 mis-attribute a hook bug as a simulation error. 

102 

103 ``on_datapoint_start`` fires inside the per-datapoint ``run_single`` task 

104 (gathered with ``return_exceptions=True``), so a raise is captured as that 

105 datapoint's error result and surfaces via ``on_datapoint_error`` + 

106 ``on_datapoint_complete`` for that datapoint only — it does NOT abort the 

107 batch. This is the same isolation behaviour as a failing target or ``run()`` 

108 call. 

109 

110 ``on_confirm`` and ``on_run_start`` run before the gather and are NOT 

111 guarded: a raise there propagates and aborts the entire run. All other 

112 per-datapoint hooks (``on_datapoint_complete``/``_error``, 

113 ``on_evaluator_complete``) are also unguarded. 

114 

115 ``on_confirm`` is the single pre-run gate (reuses the ``SimulationRunMeta`` 

116 payload). It fires before the runner/target exist; returning ``False`` 

117 aborts the run via ``SimulationCancelledError``. ``on_run_start`` fires only 

118 after ``on_confirm`` returns truthy and target resolution + runner 

119 construction succeed — gate first, then render-init. Note: for 

120 ``generate_and_simulate`` the gate fires AFTER persona/scenario/ 

121 first-message generation, so those generation tokens are already spent when 

122 ``on_confirm`` is called — the gate protects the simulation batch, not 

123 generation. 

124 

125 ``on_run_complete`` is the terminal hook. It always fires exactly once after 

126 a successful ``on_confirm`` + ``on_run_start`` pair, even on failure (e.g. 

127 a batch error or an exception during scoring). ``results`` may be an empty 

128 list if failure occurred before any results were collected. 

129 """ 

130

200 async def on_run_complete(self, results: list[SimulationResult]) -> None: 

201 """Terminal hook. Always fires exactly once after ``on_run_start``, even 

202 on failure. ``results`` may be an empty list if failure occurred before 

203 any results were collected.""" 

204 total = len(results) 

205 achieved = sum(1 for r in results if r.goal_achieved) 

206 errored = sum(1 for r in results if r.terminated_by.value == 'error' or r.metadata.get('error')) 

207 avg_turns = (sum(r.turn_count for r in results) / total) if total else 0.0 

208 broken = sum(len(r.rules_broken) for r in results) 

209 pct = (achieved / total) if total else 0.0 

210 logger.info( 

211 f'[simulation] Run complete: {total} simulations | goal_achieved={achieved}/{total} ' 

212 f'({pct:.0%}) | avg_turns={avg_turns:.1f} | rules_broken={broken}' 

213 ) 

214 if errored: 

215 logger.warning(f'[simulation] {errored}/{total} simulations errored') 

216 logger.info('[simulation] Tip: explore results with "eq dashboard .evaluatorq/sim-runs"')

497 """Record pipeline stage transitions into a `ManifestWriter`.
