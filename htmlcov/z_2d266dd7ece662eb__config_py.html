87 """Per-call timeout for the target under test, threaded into 

88 ``SimulationRunner``. Mirrors red team's equivalent knob — a slow 

89 self-hosted target needs this raised; ``EVALUATORQ_LLM_TIMEOUT_S`` only 

90 covers the simulator's own (user-simulator / judge) LLM calls.""" 

91 max_target_retries: int = Field(default=DEFAULT_MAX_TARGET_RETRIES, ge=0) 

92 """Retries for a failed target call, threaded into ``SimulationRunner``. 

93 Mirrors red team's equivalent knob.""" 

94 target_reasoning_effort: str | None = None 

95 """Reasoning effort pinned on the agent *under test* (``agent:<key>`` / 

96 bare ``<key>`` targets only) — the simulation counterpart of red team's 

97 ``LLMConfig.target_reasoning_effort``. ``None`` leaves the provider 

98 default. Distinct from the simulator's own ``EVALUATORQ_REASONING_EFFORT`` 

99 fallback (see ``simulation.agents.base``), which drives the user-simulator 

100 and judge, not the target.""" 

101 max_tool_result_chars: int = Field(default=DEFAULT_MAX_TOOL_RESULT_CHARS, gt=0) 

102 """Cap on each tool result rendered into the text the user-simulator sees 

103 for a tool-only turn (``runner.simulation._tool_traffic_text``). 500 by 

104 default; raise it for a tool-heavy agent whose results are being cut 

105 before the simulator — and the judge, which scores the same transcript — 

106 can react to them.""" 

107 per_simulation_timeout_s: float | None = Field(default=None, gt=0) 

108 """Overall wall-clock bound for one datapoint's simulation (all turns, 

109 target + user-simulator + judge calls included), applied via 

110 ``SimulationRunner._run_with_timeout`` — the same guard ``run_batch`` uses. 

111 ``None`` (the default) leaves no bound beyond the per-call timeouts 

112 (``target_agent_timeout_ms`` / the simulator's own LLM timeout): a stalled 

113 conversation was previously unbounded on the ``simulate()`` path, since it 

114 calls ``runner.run()`` per row instead of ``run_batch``. ``None`` is the only 

115 spelling of "unbounded" — ``gt=0`` rejects ``0`` and negatives at construction, 

116 which the ``timeout_s <= 0`` sentinel downstream would otherwise read as 

117 unbounded, the opposite of what typing ``0`` means."""
