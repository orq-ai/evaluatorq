Interviewer question bank — Arian's cards

Clay border = ask it. Olive border = Bauke's intro should already cover it — keep as a backup reformulation if the intro ran thin. Each card: the question as Arian asks it, the beats Bauke hits, and the cue.

Q0 · "So in one sentence — what did we just watch?"
Backup only: the intro (03:00–08:00) answers "what does it do" and "what problem does it solve". Use this reformulation after Act 1 if the intro was rushed — it gives Bauke a clean recap beat: synthetic users stress-test your agent in multi-turn conversations, and a judge tells you where it breaks.
Cue · only if needed, after Act 1 step 4
Q1 · "What do we actually need to use this? What's the shopping list?"
Beats for Bauke:
  • Python 3.10+, pip install evaluatorq — that's the install.
  • An LLM key for the simulator and judge (OpenAI key or orq key — the sim's own brains).
  • Your agent: an orq agent key, any OpenAI-compatible endpoint, an HTTP URL, or a Python callback.
  • Punchline: no dataset, no labels, no annotation budget.
Cue · Act 1, while `sim generate` streams (~08:30)
Q2 · "Hold on — walk me through what it just generated. What am I looking at?"
The payoff question. Bauke opens one JSONL row and reads it like a character sheet: persona (patience, assertiveness, style, emotional arc, background) × scenario (goal, context, pass/fail criteria). Arian's follow-up jab: "Would you have written that test case yourself?" — the honest answer is no, and that's the point.
Cue · Act 1 step 2, JSONL open on screen
Q3 · "The user-simulator got impatient with the agent just now. Who decided it should be impatient?"
Lands during the live run when a persona's style shows in the transcript. Beat: personality comes from the generated persona — emotional arc is scripted, the conversation is not. This separates simulation from "replaying canned prompts".
Cue · Act 1 step 3, mid-simulation, react to a real transcript moment
Q4 · "Is this open source? Because most people watching don't run their agents on orq."
Ask it bluntly — it's the audience's biggest silent objection. Beats:
  • Yes — evaluatorq is open source (github.com/orq-ai/evaluatorq), pip-installable, runs anywhere.
  • The simulation engine has no platform dependency: --openai-model for any OpenAI-compatible endpoint (vLLM, OpenRouter, local), --vercel-url for any HTTP agent.
  • SDK: wrap any async fn(messages) → str. Adapters shipped for LangGraph, CrewAI, OpenAI Agents SDK, Pydantic AI.
Cue · opens Act 2 (~20:00) — this question IS the act transition
Q5 · "So minimum viable start: I have a LangGraph agent on my laptop. What are my first three commands?"
Forces concreteness. Bauke's answer: ① pip install evaluatorq ② export your LLM key ③ evaluatorq sim run --agent-description "..." or ten lines of SDK (simulate(target_callback=...)). Under five minutes to first transcript.
Cue · end of Act 2, before Act 3
Q6 · "We've got results on screen. Teach me to read them — what do I look at first?"
Beats:
  • Pass rate first — then ignore it. It says that something broke, never what.
  • Open a failing transcript. Find the turn where it derails — usually a mid-conversation pivot, not turn one.
  • Read the judge's reasoning per turn (goal_achieved, criteria_met) — it's an explanation, not just a score.
  • Frame: every failure is a bug report with the reproduction attached — persona + scenario + transcript.
Cue · interview block opener (~33:00), run viewer still fresh in memory
Q7 · "OK, I found the failure. What's the workflow from here — what do I actually do?"
Beats: fix the prompt/tool → re-run the frozen datapoints (--datapoints file.jsonl) → compare like-for-like → regressions become a gate, not a surprise. Wire it into CI: the suite runs on every agent change like unit tests. The dataset can also graduate to the orq platform for team-wide experiments.
Cue · interview block, directly after Q6
Q8 · "Can I drive this from Claude Code? Could a coding agent run the whole loop for me?"
Beats:
  • Yes — it's CLI-first with machine-readable output, which is exactly what coding agents want.
  • The loop: Claude Code runs sim run, reads the failing transcripts, patches the system prompt, re-runs the frozen set, shows you the diff. Human reviews, agent iterates.
  • Honest note: the human stays on the diff. You're reviewing changes, not writing test cases.
Cue · interview block (~36:00)
Q9 · "That's basically a self-improving agent. Is that safe? What goes wrong?"
The expert-credibility card — invite Bauke to caveat:
  • The frozen suite works as a fitness function for automated iteration — that part is real.
  • The trap is Goodhart: optimize hard against one judge and you overfit to the judge, not the user.
  • Mitigations: hold out scenarios the loop never sees; extend the suite as the agent improves; periodically eyeball transcripts yourself.
Closing beat: simulation doesn't replace production data — it's how you start before you have any, and the suite keeps growing after.
Cue · interview block closer (~38:00), hand off to audience Q&A

Demo cue sheet — exact commands

Mirrors RUNBOOK.md in the repo (examples/agent_simulation/webinar_demo). Fill the <ics-agent-key> placeholders before going live.

Act 1 — from scratch (08:00)
# 1. generate from the agent's own description
uv run evaluatorq sim generate \
  --target agent:<ics-agent-key> \
  --num-personas 3 --num-scenarios 3 \
  -o ics_datapoints.jsonl

# 2. the payoff — read one generated row aloud
uv run evaluatorq sim validate-dataset ics_datapoints.jsonl

# 3. run live, freeze the set for Act 3
uv run evaluatorq sim run \
  --target agent:<ics-agent-key> \
  --save-datapoints ics_datapoints.jsonl \
  --name ics-from-scratch

# 4. pass rate + a failing transcript
uv run evaluatorq sim runs
uv run evaluatorq sim ui .evaluatorq/sim-runs/<run>.json
Act 2 — non-orq agents (20:00)
# CLI: any OpenAI-compatible endpoint
uv run evaluatorq sim run --openai-model gpt-4o-mini \
  --agent-description "Support agent for ..." \
  --name ics-nonorq-cli

# CLI: any deployed HTTP agent
uv run evaluatorq sim run \
  --vercel-url https://my-agent.vercel.app/api/chat \
  --agent-description "..."

# SDK: wrap anything that answers a message
from evaluatorq.simulation import simulate

async def my_agent(messages) -> str: ...

results = await simulate(
    target_callback=my_agent,
    evaluator_names=["goal_achieved",
                     "criteria_met"])
Act 3 — working with data (27:00)
# 3a. re-run the EXACT same set after a prompt tweak
uv run evaluatorq sim simulate \
  --target agent:<ics-agent-key> \
  --datapoints ics_datapoints.jsonl \
  --name ics-rerun

# 3b. extend the suite — generate more, append
uv run evaluatorq sim generate \
  --target agent:<ics-agent-key> \
  --num-personas 2 --num-scenarios 2 -o more.jsonl
cat more.jsonl >> ics_datapoints.jsonl
uv run evaluatorq sim validate-dataset ics_datapoints.jsonl

If it breaks — contingencies & honest answers

First three are demo failures with a rehearsed fallback. Last three are audience questions that deserve an honest "not yet" — saying it confidently is part of the "this is new and moving fast" story.

Situation
Sev
Response
Live ICS agent unreachable mid-demo (platform hiccup, key expired).
HIGH
Switch to --agent-description "..." — no platform call needed for generation; for the run, fall back to the --openai-model stand-in agent rehearsed in the dry run. Narrate the switch: "this also shows it works without orq."
Generation or simulation runs slow on the stream — dead air.
HIGH
Arian fires Q1/Q2/Q3 to fill (that's what the cues are timed for). If >2 min, open backup_datapoints.jsonl / the pre-baked run JSON in sim ui and keep the live one running in a second tab.
sim ui fails to open or renders wrong on the shared screen.
MED
Fallback: sim runs table in the terminal + open the run JSON directly and read the failing transcript from it. Less pretty, same story.
"Can I push the suite to an orq dataset and run from there?"
MED
Honest answer: the CLI round-trip is rough today (dataset rows need stringified persona/scenario; no --dataset-id flag — dataset-backed runs are SDK-only via simulate(dataset_id=...)). Demo the local JSONL path; platform round-trip is on the roadmap.
"Why is there no orq sim command?"
LOW
Deliberate split: orq CLI = platform CRUD (agents, datasets, evals); evaluatorq = the open-source evaluation engine. Simulation lives with the engine.
"Can it seed from my existing data AND generate more in one go?"
LOW
Not natively yet — dataset_id is mutually exclusive with personas/scenarios/datapoints. Today: generate separately and append (Act 3b shows exactly this). Say so plainly.
